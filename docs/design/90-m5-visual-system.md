# M5 视觉系统与面板壳（草案 v1，2026-11-26）

> 状态：**待拍板**。本文件把用户扔过来的 7 条设计意图落成可执行的规则、架构和里程碑；技术细节在 M5.0 spike 后回填。
> 前置阅读：[50-visual-tokens.md](50-visual-tokens.md)（色卡语义化 v0）、[frontend-design-tech.md](../recon/frontend-design-tech.md) §5（安卓玻璃能力矩阵）、[70-base-first-plan.md](70-base-first-plan.md)。
> 现有 M1–M4 的成果不是废稿：数据/交互契约（事件流、会话树、滚动、返回语义）全部保留，M5 换的是**外观与壳**。

## 0. 一句话

M5 交付两样**可复用资产**，而不是"给现有页面化妆"：

1. **视觉原语层**：tokens（颜色/字阶/间距/半径/光照/动效）+ primitives（超椭圆表面、新拟物浮雕、液态玻璃、图标、输入、列表、按钮）；
2. **面板壳**：一套可组合的"无限抽屉"——面板按图邻接，左右滑动换面板，所有面板共用同一套手势/动画/返回逻辑。

三块现有页面（聊天 / 会话抽屉 / 设置）是这两个资产的第一批应用，被**重做**而非微调。

**M5 不做**：插画、主题商店、全局面板折射（L3）、接口自定义编辑器（先把图定义与运行时做好，编辑器留 M6）、打包品牌字体。

## 2. 视觉系统

### 2.1 层模型（先定层级，再谈材质）

| 层 | 内容 | 材质 | 是否模糊背后 |
|---|---|---|---|
| L0 背景 | 页面底色、极轻的氛围渐变 | 纯色/双色极缓渐变 | — |
| L1 结构面 | 面板本体、卡片组、抽屉 | 不透明新拟物（Raised / Inset） | 否 |
| L2 浮层 | 输入区、搜索框、顶栏、独立按钮、Sheet | 液态玻璃（tint + 边缘折射 + 高光） | 是（L1 级，≤3 面） |
| L3 内容 | 文字、图标、图片 | 无表面 | — |

规则：
- **描边不是层级手段**。层级只用"投影 + 明度差 + 玻璃高光"表达；禁止 1dp 灰线画卡片轮廓。
- 同一屏可见的**玻璃面 ≤3 个**（输入区、顶栏、抽屉搜索 = 正好 3 个），其余全部不透明。
- **投影颜色取面板自身颜色**（2026-11-27 拍板）：粉气泡=粉影、绿按钮=橄榄影；中性表面仍用派生中性影。
- **同级阴影不遮挡**：用 `NeoSiblings(gap)` 声明同级间距，阴影最大外扩 = gap/2；一个按钮的投影不会盖到旁边同级按钮上（2026-11-27）。
- 列表行内部**不逐行加浮雕阴影**（性能与视觉噪声双杀），分组靠间距 + 底色差。

### 2.2 形状：Superellipse

用户给的参数曲线是正确的 Lamé 超椭圆：`|x/a|^n + |y/b|^n = 1`，其参数式为

```
x = a · |cos t|^(2/n) · sign(cos t)
y = b · |sin t|^(2/n) · sign(sin t)
```

`n = 4` 即经典 squircle（iOS 圆角约 n≈5）。落地为 Compose `Shape`：

```kotlin
class SuperellipseShape(
    val radiusX: Dp, val radiusY: Dp = radiusX,
    val nX: Float = 4f, val nY: Float = 4f,
) : Shape {
    // 实现要点：
    // 1) 每个角只算 90° 弧段（t ∈ [0, π/2]），中间是直边——不是整圈采样后再裁；
    // 2) 每段采样 12 点，用 Catmull-Rom → 三次贝塞尔拟合（纯折线在大半径下会有可见棱）；
    // 3) Path 按 (w,h,r,n) 缓存（LruCache 64 条），createOutline 里不重新算数学；
    // 4) 同时实现 CornerBasedShape 语义，使 clip/background/border/shadow 全走同一轮廓。
}

// 胶囊（全圆）：a=b=高/2, n=4 的超椭圆比正圆更"肉"一点，作为按钮/标签的统一形
fun squircleCapsule(height: Dp) = SuperellipseShape(height / 2, height / 2, 4f, 4f)
```

**禁止**：普通 `RoundedCornerShape` 出现在新 UI 里（旧页面迁移完即删）。按钮、输入、卡片、面板、Sheet 一律超椭圆。

### 2.3 材质：四种 Surface

| 材质 | 视觉 | 用途 | 实现 |
|---|---|---|---|
| `Raised` | 外凸浮雕 | 面板、卡片、主按钮 | 双外阴影：亮 -offset / 暗 +offset（用户给的 45px/22px 公式的 dp 化），面内叠 2–4% 的顶亮底暗渐变 |
| `Inset` | 凹陷 | 搜索框底槽、分段控件选中槽、开关轨道 | 双内阴影（inset 版），面内叠反向渐变 |
| `Float` | 悬浮卡片 | 消息气泡、菜单、提示卡 | 单侧柔和阴影 + 1 级抬升（比 Raised 更轻，不抢结构面） |
| `Glass` | 液态玻璃 | 输入区、顶栏、抽屉搜索、独立按钮 | tint（低透明）+ 背后模糊（分级）+ 边缘菲涅尔 + 高光块 + 内透射 tint |

新拟物阴影公式 dp 化（用户 22/45 是 px 级视觉，按**面板半径**等比缩放）：

```
offset = radius * 0.40        // 例：R=28dp → 11.2dp（对标 80px 圆角 / 33px 偏移 / 66px 模糊）
blur   = offset * 2.0         // ≈22dp（模糊半径 = 0.8 × 圆角，与参考一致）
亮影   = 光源侧（左上），alpha 0.55–0.75（深色模式降到 0.18–0.28）
暗影   = 背光侧（右下），alpha 0.35–0.45（深色模式改为"更深"而不是"更灰"）
```

暗色模式不是把浅色反过来：底色 `#161412`，亮影是**更低明度的暖白**（`#241F1A` 一类），暗影是**更深的黑**，否则会出现"脏灰边"。两者按色卡派生，不硬编码。

性能策略（spike 必须实测）：
- 阴影用 `graphicsLayer { renderEffect = BlurEffect(...) }`（Android 12+ 才真模糊）；更低版本降级为 3 层偏移低 alpha 硬边（视觉略糙但零成本）；
- 每个 Surface 的阴影**按尺寸缓存**（尺寸不变就不重算 RenderEffect 参数），滚动中不产生新 layer；
- 一屏真正带模糊阴影的 Surface ≤8 个（面板 3 + 卡片组 3 + 按钮 2），其余用 Flat 表面。

### 2.4 颜色：四色卡的分工

| 令牌 | 浅 / 深 | 用途 | 禁令 |
|---|---|---|---|
| `bg` | `#FAFDF3` / `#161412` | 页面底 | — |
| `accent.moss`（绿） | `#B0C591` / `#AEC983` | 主操作、选中、焦点 | 不作大面积底色 |
| `tint.moss`（浅绿） | `#E3EBD2` / `#EBEDB7` | 分组底、次级容器 | 不与 `accent.moss` 同屏大面积叠用 |
| `accent.blush`（粉） | `#FFD7D2` / `#F3BFA5` | **身份标记**：用户消息、未读点、"她"的标记 | 不作按钮主色 |
| `accent.cream`（暖白） | `#FFEBE9` / `#FFDBB2` | 提示、记忆/主动消息的暖提示 | 不作正文底色 |
| `rim`（发光） | 深色 `#E09A42`，浅色不用 | **仅**玻璃边缘高光/焦点光晕，≤12% alpha | 大面积填充、多个卡片同时出现 |

规则：**一屏最多 1 个主色（绿）+ 1 个辅色（粉或暖白）**。粉绿叠层的正确用法是"绿是结构/操作，粉是身份/情绪"，被玻璃层叠后自然出现冷暖对照，而不是把两种颜色都倒进渐变里。

### 2.5 光照模型（暗色模式的重点）

不是画一条亮边，而是模拟三件事：

| 要素 | 物理 | 实现 | 分级 |
|---|---|---|---|
| 边缘菲涅尔 | 掠射角反射率升高 | 沿轮廓的多段渐变（边缘 0→2dp 内 alpha 0.5→0，不是等宽 1dp 线），按光源方向调制上下左右的强度 | 全版本 |
| 镜面高光块 | 光源在玻璃上的倒影 | 一个随光源方位放置的径向高光（`Brush.radialGradient`，`BlendMode.Screen`），形状被 Surface 轮廓裁切；拖动面板时高光按位移**缓慢偏移**（视差） | 全版本（低成本） |
| 透射/折射 | 背景色透过玻璃并被边缘弯曲 | L0：背景色 tint（alpha 0.06–0.16）+ 边缘内侧一条反色细渐变；L2：AGSL `RuntimeShader` 做 UV 偏移 + 1–2% 色散 | L0 全版本 / L2 仅 API33+ 且仅输入区 |

光源是 token：`LightRig(azimuth = 135°, elevation = 55°, key = 0.85, fill = 0.25, rim = 0.4)`。所有 Surface 读同一个 rig（可随系统深色模式微调），保证全屏光向一致。**禁止**每个组件自己写一套渐变角度。

### 2.6 图标

- 规格：24dp 网格、1.5dp stroke、圆头圆角、光学对齐（视觉重心比几何中心略高 0.5dp）；
- 实现：`MycoIcons` 手写 `ImageVector`（path 数据 20 个核心图标，不引第三方图标库，避免风格不一 + 包体）；
- 首批 20 个：menu、back、close、more、search、plus、send、stop、mic、attach、copy、regenerate、branch-left、branch-right、check、chevron-down/right、trash、archive、settings、clock（思考/过程）、globe（搜索）、spark（记忆/主动）。
- 全面清除 emoji 与文字代图标：`☰ ‹ › ▸ ▾ 🎤 ＋` 全部替换；空态也不再放符号。

### 2.7 动效：三套曲线 + 一个原则

| 名称 | 参数 | 用途 |
|---|---|---|
| `settle` | `spring(dampingRatio = 0.86, stiffness = 420)` | 面板吸附、展开/收起、Sheet |
| `snap` | `spring(dampingRatio = 0.92, stiffness = 900)` | 开关、选中、按压回弹 |
| `glide` | `splineBasedDecay`（滚动）/ `exponentialDecay`（拖拽释放） | 惯性滑动 |
| `fade` | 180ms `FastOutSlowIn` | 仅跨屏淡入（内容不位移的场合） |

**原则：跟手 1:1，释放必须有速度。** 用户说的"手停了它还会顿一下"根因是松手时用 tween 从当前值补到终点（速度不连续）。修法：手势期间只改 `progress`；松手时把 `VelocityTracker` 的末速度传给 `Animatable.animateTo(target, initialVelocity = v)`，由 spring/decay 决定轨迹，不做定长补间。现有 `PredictiveNavState.exit()` 也换成这个模式（保留 API，只换内部物理）。

禁止：`tween(320)` 这类"看起来像动效"的定长补间出现在拖拽释放里；禁止弹跳（`dampingRatio < 0.8`）；同一屏同时运行的动效类别 ≤3。

**按压（2026-11-27 拍板）**：按钮语义优先凸起；点击时凸起"被按凹"（外阴影收缩 → 内阴影渐入，release 用 spring 回弹），并按触摸点画**超椭圆裁切的扩散波纹**。Material 矩形 ripple 一律关闭（`indication = null`）。玻璃面同样有按压：边缘变亮、投影收缩、波纹相同。

### 2.8 排版与栅格

- 间距：4dp 基数（4/8/12/16/24/32/48）；**面板版心**：面板外距 8dp，面板内距 16dp，组间 12dp，行内 8dp；
- **同心圆角规则（强制）**：`r_child = r_parent − gap`，min 4dp。例：面板 28 → 卡片 20 → 控件 12 → 内嵌槽 4。所有嵌套圆角由 `LocalRadiusScope` 自动推导，组件不允许自己写数字。这条同时解决用户说的"半径必须严格按大小匹配"；
- 字阶（中文，行高按 1.55–1.65）：

| 名 | 大小/行高/字重 | 用途 |
|---|---|---|
| caption | 11/16/400 | 时间戳、meta |
| label | 13/18/500 | 按钮、标签、辅助信息 |
| body | 16/26/400 | 消息正文（保持现有，阅读最佳） |
| title | 17/24/600 | 顶栏、卡片标题、会话名 |
| headline | 20/28/600 | 页面大标题、空态 |
| display | 28/36/600 | 仅空态/品牌位 |

- 触摸目标 ≥48dp（工具行视觉可 32dp，靠 8dp 内边距补足热区）；图标按钮视觉 24dp + 12dp 内边距补足；
- 输入区比例（2026-11-27）：文本区 ≥44dp 高，工具行按钮统一 32dp——按钮不得大于可输入区域；
- 响应式：宽度 ≥600dp 切双栏 profile（见 §3.5）；字号跟随系统缩放，不另做密度档。

## 3. 面板壳：可组合的无限抽屉

**渲染语义（用户 2026-11-26 澄清，优先级最高）**：这里的"抽屉/接口"是**抽象结构**，不是并排拼贴。
新面板仍然以**层叠覆盖**的方式出现——从一侧滑入、压暗并轻微缩小底层，退出时反向；**最终外观与现在的结构一模一样**（聊天底、抽屉遮罩滑入、设置整页覆盖）。
"接口"是**数据**：某面板的某个边可以接哪张面板；不是可见的抓手，也不是屏幕边缘手势的新入口。

### 3.1 模型

```kotlin
enum class PanelEdge { LEFT, RIGHT }

data class PanelSpec(
    val id: String,
    val kind: PanelKind,          // Chat / SessionList / Settings / Bin / Work...
    val edges: Map<PanelEdge, String> = emptyMap(),  // 抽象接口：从哪个边打开谁
)

class PanelGraph(val specs: Map<String, PanelSpec>, val rootId: String)
// chat profile: chat[LEFT] = sessionList, chat[RIGHT] = settings
// work profile: 同一套壳换一张图

class PanelHostState(graph: PanelGraph, initial: String) {
    var currentId: String
    val stack: MutableList<Entry>   // 每层记录：从哪个面板、从哪个边打开
    // open(edge) / pop() / predictiveBack(progress)
}
```

- 打开邻接面板 = **入栈 + 从对应边滑入覆盖**；返回 = 出栈 + 反向滑出；栈空 = 退出 app（与已确认返回语义一致）。
- 底层始终是聊天根层；被覆盖的层不做布局重算（聊天滚动状态照旧 hoist，不重建）。
- 图是纯数据：M6 做"用户自定义哪里接什么"只改这张图，不动壳代码。

### 3.2 手势与入口

- **不新增屏幕边缘手势，不做可见抓手**。入口沿用现有：抽屉从顶栏菜单/左缘滑入，设置从顶栏菜单打开，回收站从设置进。
- 与系统预测式返回复用同一物理：`PredictiveNavState` 的 progress 从"页面退出"泛化为"当前层退出"，`exit()` 内部换成"松手速度驱动"（§2.7）。
- 冲突规则保持现状：抽屉手势仅在聊天层启用；设置/回收站层不响应抽屉手势；屏幕边缘 20dp 内交给系统。

### 3.3 层叠视觉（与现状一致，只统一 token）

- 底层：`scale 1 → 0.96`、`alpha → 0.5`、可选 `blur 0→4dp`（仅 API31+，失败静默跳过）；
- 新层：从对应边滑入（`translationX: ±W → 0`），`Float` 材质浮起，顶部圆角按 §2.8 同心规则；
- 遮罩：`0.32 * progress` 的暗化（现有实现保留），不加描边；
- 不允许并排/分栏（宽屏 profile 除外，见 §3.5）。

### 3.4 接口的可发现性

- 接口不可见（数据）；发现路径是显式按钮/菜单，不是抓条；
- 长按面板标题可显示"这块面板左右各能接什么"（只读提示，M6 演化为编辑器）；
- 首次进入某层不做呼吸/提示动画（避免新装饰）。

### 3.5 宽屏

宽度 ≥600dp：聊天与列表并排（同一张图的宽屏 profile，抽屉退化为常驻）；这是唯一允许"并排"的场合，因为它不依赖滑动接口。

### 3.6 chat / work 的分化

- 面板 `kind` 不感知 chat/work；两种模式各自一份 `PanelGraph` + 一份主题 accent（chat 用 moss，work 可用 blush/cream 作身份色）；
- M5 只交付 chat 图（chat 左会话右设置）；work 图等 M6 有真实 work 面板时再接，壳不改。

## 4. 页面重做清单

### 4.1 聊天页
- 顶栏：玻璃浮条（不是通栏），左图标 menu、中间标题（长按复制/重命名）、右 more；**不用文字按钮**；滚动时顶栏收窄为"标题 + 细进度"。
- 消息节奏：角色区分靠**排版**而不是气泡——助手全宽正文（16/26），用户消息用 blush 色低透明浮动卡片（Float）+ 右侧缩进 12%；turn 之间加 1 个 `settle` 间隔（16dp），不再堆 meta 小字；`▍` 光标换成 2dp 宽的圆头竖条（呼吸 alpha，不闪）。
- 过程/思考折叠：抓条式 header（图标 + 摘要 + 状态点），展开时按 §2.1 的 Inset 表面呈现，行距 12；内部滚动保持现有隔离。
- 输入区（重点重做）：一个 Glass 大圆角浮岛（radius = 高度/2 的 squircle，随行数长高但保持同心），内部拆三层：
  1. 文本区（透明、无边框，placeholder 只一行）；
  2. 底部工具行：左「+ 附件」「模型/思考」胶囊，右发送/停止（图标按钮，主态用 `accent.moss` 填充，禁用态用 Inset 凹槽）；
  3. 上下文标签（thinking/search）做成可移除的小胶囊（不是 FilterChip），放在文本区下方左对齐。
  - 键盘弹出时面板上移但不改变输入区内部布局；发送后键盘不自动收（待办已记，M5 修）。
- 空态：品牌位 display 字 + 两个建议问题卡片（Raised），不用圆形装饰。

### 4.2 会话抽屉（左面板）
- 顶部：玻璃搜索框（Inset 底槽 + 图标）+ 新建按钮（Raised 圆形，`accent.moss`）；
- 分组：置顶 / 今天 / 最近 7 天 / 更早，组头是 label 字，不做吸顶（避免与聊天页 sticky 规则混）；
- 行：标题（单行横向滚动，保留现有）+ 右侧时间 + 未读点（blush）；长按弹 Float 菜单（重命名/归档/删除）；
- 底部：设置入口（图标 + label，Raised 胶囊），不再用文字按钮。

### 4.3 设置页（重点：减法）
- 拆成两层：
  - **用户层**（默认可见）：外观（跟随/浅/深 + 强调色预览）、对话（字体大小、发送后键盘、流式滚动）、记忆与主动、通知、关于；
  - **运维层**（折叠进"高级"子面板）：模型服务、provider 管理、自检、常驻服务、导入导出、诊断开关。
- 模型逻辑重做：不再直接暴露 JSON 字段。"添加模型服务"= 向导：选预设（DeepSeek/OpenAI 兼容/本地）→ 填 Base URL + Key → 点"测试连通"（成功才亮下一步）→ 勾选模型（预填 context window，可高级展开）→ 保存。支持多 provider 时用**卡片列表**（名称 + 状态点 + 当前模型），点卡片进入编辑。
- 每个设置项必须能被普通用户理解：文案不出现 `revision`、`provider`、`auth ref` 这类内部词（内部信息收进"高级/诊断"）。
- 搜索设置保留（用户已用），但结果按"用户层"优先。

### 4.4 回收站/归档（面板）
- 复用列表 primitives + 玻璃搜索框；空态用 headline 文案，不用符号。

## 6. 风险与降级

| 风险 | 影响 | 降级/对策 |
|---|---|---|
| 双阴影逐帧模糊开销 | 滚动掉帧 | 尺寸缓存 + 一屏 ≤8 个 + 低端机降级为硬边 |
| 真背景模糊不可依赖（<API31，或部分 ROM） | 玻璃变"半透明塑料" | GlassCapability 分级，默认跟随设备；L0 仍是一等视觉（tint + 菲涅尔 + 高光），不是残废态 |
| Superellipse 与 Compose Shape 的裁剪/点击边界 | 点击判定与视觉不符 | 用同一 Path 做 clip 与命中；spike 验证"角落外侧 2dp 点击是否穿透" |
| 面板手势与系统手势/内层滚动打架 | 误滑 | 边缘 20dp 让给系统 + 方向锁 + 组内滚动隔离（既有） |
| 设置减法砍掉用户需要的能力 | 找不到入口 | 运维层收进"高级"，不删除功能；加设置搜索 |
| 面板壳改动面大 | 导航回归 | M5.2 前先写返回语义测试清单；壳与面板内容解耦，逐面板迁移 |
