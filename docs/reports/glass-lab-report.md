## 1. 一句话结论

1. **`record + drawLayer` 的捕获路径已修复并验证可用**（见 §2 与 §11）：之前失败是用了 `GraphicsLayer.record(density, layoutDirection, size, block)` **成员函数**；换成 `GraphicsLayer.record(IntSize) { … }` 扩展后层里就有内容了 → **真 backdrop 捕获 + 多块玻璃共享一次捕获** 是本机的主路径。
2. **重绘路径（面板内重绘背景 + `RenderEffect.createBlurEffect`）作为对照/降级保留**：视觉与捕获路径一致，代价是每块玻璃每帧多画一遍背景。
3. 模糊半径 8→32dp 的可读性衰减非常快（§4）；**32-48dp 这类大半径在正常 UI 文本上"看不出模糊"，只会把细节平均掉**——这正好解释了 DSH 浮层"弱到截图看不出来"的观感（§6）。
4. 玻璃叠玻璃：**每层都采样原始背景**可以叠 2~3 层；**后层采样已合成结果**会累积去饱和/发暗，2 层可接受、3 层开始明显"脏"（§5）。
5. 帧时间：模拟器基线本身就是 P50 ≈ 25ms；加 1 层玻璃 → P50 ≈ 31ms，2/3 层 ≈ 32ms（不随层数线性增长，本机瓶颈在模拟器合成/呈现）。**真机数据未知，本机不能证明 60Hz 能撑住**（§8）。

## 2. `record + drawLayer`：第一版失败 → RCA 修正（已被 §11 取代）

> **2026-11-27 修正**：第一版结论"本机捕获路径不可用"**是错的**，根因是调错了重载：用了 `GraphicsLayer.record(density, layoutDirection, size, block)` **成员函数**（它不会把外层 `ContentDrawScope` 的 canvas 重定向到层里，于是 `drawContent()` 画到了窗口 canvas、层的 display list 一直为空）。正确写法是 `GraphicsLayer.record(IntSize) { … }` 扩展——源码证据 `compose-ui 1.7.5 DrawScope.kt:938-956`。修正后捕获路径工作正常，见 §11 的 `20/21-rca-capture-verify*.png`。
>
> 下面保留当时的三组交叉实验记录，作为"成员函数 vs 扩展"对照的历史证据。

`06-capture-path-unavailable.png` 是诊断场景 `glass_scene=capture-diag`，三组交叉实验：

| 实验 | 做法 | 结果 |
|---|---|---|
| A | 直接 `drawRect` 录进 `GraphicsLayer`，在**兄弟节点** `drawLayer` | ✅ 绿块正常出现 → 跨节点绘制机制本身没问题 |
| B | `layer.record { this@drawWithContent.drawContent() }` 录子内容，兄弟节点画 | ❌ 区域空白；内容只出现在"记录它的那个节点"上 → `drawContent()` 把内容画进了外层画布，没进 layer |
| C | 真实背景捕获层（`layer.size = 1080×1953`，已确认有尺寸）→ 兄弟节点缩放 0.18 画 | ❌ 空白 |

补充事实（logcat）：
- `layer.size=1080x1953` 正常；`toImageBitmap()` 能返回 1080×1953 的 HARDWARE bitmap（说明层的"尺寸/生命周期"没问题，是内容没录进去）。
- 同一节点里 record 后连画两次（第二次缩 0.15），第二次也画不出来 → 层内容确实为空。
- 换成 host GPU（AMD 890M）后结论不变 → **不是软件渲染导致的**。
- 该路径正是 Haze 等库的做法；本机不可用说明"库机制本身"在这套 Compose/设备组合上不成立，**必须在真机上复核**（这一项已交给另一路深挖，本报告不展开）。

> 因此本实验页的玻璃面板统一改成 **`BackdropPainter` 重绘路径**：把同一份背景内容按面板位置平移后再画一遍，挂在 `graphicsLayer { renderEffect = … }` 里做模糊。
> 代价：每帧每块玻璃多画一遍背景（背景已改为单 Canvas 程序化绘制，重绘一份约几十个 draw call）。

## 4. 每种效果到底渲染出了什么（可判断描述）

背景统一是「有内容的后台」：14sp/11sp/9sp 文字、2dp 级棋盘、彩色块、色相条、图片感渐变。

| 效果 | 渲染结果 | 可判断描述 |
|---|---|---|
| 单层真模糊 24dp（重绘路径） | ✅ 正常 | 24dp 下 14sp 正文变灰雾、勉强可读；11sp 已不可读；棋盘硬边完全消失；边缘有 1.2dp 高光、内阴影，玻璃有厚度感 |
| 只有 tint（无模糊） | ✅ 正常 | 内容锐利，只整体发白/轻微降对比；**用 tint 冒充玻璃一眼能看出"没糊"** |
| 半径 8dp | ✅ | 文字轮廓仍在但发虚；棋盘变成柔和的块 |
| 半径 16dp | ✅ | 14sp 可读、11sp 糊；色块边界软化 |
| 半径 24dp | ✅ | 正文勉强可读，小字不可读，接近"雾面玻璃" |
| 半径 32dp | ✅ | 只剩大色块/明暗，任何 ≤14sp 文本不可读 |
| 半径 40/48dp（浮层档） | ✅ | 在「棋盘细线」这种高频细节上**看不出模糊**，只看到细节被平均成均色（黄+黑 → 橄榄色）；观感由 tint 决定 → 与 DSH「弱到截图看不出来但加分」一致 |
| 饱和度补偿 1.2 / 1.5 / 1.8 | ✅ | 1.0 模糊后明显发灰；1.5 接近原饱和；1.8 高饱和区开始过冲（色相条上能看出来） |
| 边缘高光 35%+内阴影 10% | ✅ | 1.2dp 白边 + 内沿明暗，"像玻璃"主要靠这一层；100% 时边缘发白、像塑料 |
| 磨砂噪声 1.2% / 2.8% | ✅ | 低强度只消除"塑料感"；2.8% 肉眼能看颗粒但可接受；再高会脏 |
| AGSL 伪折射 6/16dp | ⚠️ 可渲染但**只作用于自身内容** | 边缘位移/放大肉眼可见；**不能采样背景**（官方口径：输入是所在 RenderNode 的内容），且作用到整块会把文字一起拉弯（反例） |
| 双层 / 三层叠加 | ✅ | 见 §5 |
| 降级假玻璃（API<31 路径） | ✅ 可渲染 | 半透明+渐变+噪声+高光；背景内容**锐利**（不采样），观感是"半透明面板"而不是"磨砂玻璃"；不会崩 |
| 窗口级模糊 | ⏸ 未做（已移交另一路） | 本机 `isCrossWindowBlurEnabled=true` 不等于画面真糊；对比实验交给窗口模糊方向 |
| 捕获层路径 | ❌ 本机不可用 | 见 §2 |

> 注：本机是**模拟器 host GPU**。"能渲染"只说明 API/管线成立，**不代表真机帧率**。

## 5. 分层遮挡结论

`03-stack-2layers.png` / `04-stack-3layers.png`（左列 A = 每层都采样原始背景；右列 B = 后层采样"已合成结果"）：

- **后层（上层玻璃）采样到的是什么？**
  - A 方案：**采样原始背景**（不含下层玻璃）→ 重叠处只是 tint 叠加，模糊不累积，画面保持干净；
  - B 方案：**采样已合成结果**（背景 + 下层玻璃）→ 模糊会逐层累积，且下层玻璃的 tint/rim 会被再模糊一次。
- **重叠处观感**：B 方案重叠区**更暗、更灰、饱和度下降**（2 层已可见轻微"渍"感；3 层紫色渍感明显、细节丢失）；A 方案 3 层仍然干净。
- **实测判断（本机）**：
  - **最多 2 层玻璃**叠加且不显脏（B 方案）；
  - **3 层**只建议在 tint ≤6%、且重叠面积小时使用；3 层以上明显变脏，不建议；
  - 若必须 3 层以上（如抽屉 + sheet + toast），控制手段：每层 tint 降到 2-4%、只在最上层做 rim/噪声、下层不要用高饱和 tint。
- 真实产品里"每层采样已合成结果"是系统 backdrop 的天然语义（窗口背景就是最终合成），所以**B 方案才是要评估的形态**。

## 6. DSH 浮层取向（32/40/48dp）的观察

`10-subtle-32-40-48dp.png`：三块玻璃都叠在「2dp 棋盘细线」上：
- a. `blur 32dp + tint 4%`：细节被抹平、几乎无色偏 → **最接近"看不出来但加分"**；
- b. `blur 40dp + tint 8% + saturate 1.5`：更"磨砂"、暖一点（saturate 补偿），细节更不可辨；
- c. `blur 48dp + tint 2%`：最"清晰透明"，但本机半径继续加大**并没有更明显的模糊感**（细节早已被平均），差别主要在 tint。

结论：**在 30-48dp 档位，"半径再大"对观感贡献很小，tint/saturate/rim 才是决定气质的变量**；同时大半径在这些档位的帧时间没有可测差异（§8）。给产品的含义：**浮层用 32-40dp + tint 4-8% 即可**，不必为了"更明显"继续加半径。

## 7. API 门槛表

| 效果 | 最低 API | 需要硬件加速 | 需要独立窗口 | 本机结果 |
|---|---|---|---|---|
| `RenderEffect.createBlurEffect`（真模糊） | **31** | 是 | 否（in-app） | ✅ |
| `ColorMatrix` 饱和度/亮度补偿（挂在 blur 后） | 31（随 RenderEffect） | 是 | 否 | ✅ |
| `rememberGraphicsLayer` 捕获层 | 29（Compose 1.7 的 GraphicsLayer 实现） | 是 | 否 | ⚠️ 层能建、内容录不进去（本机） |
| `Modifier.blur()` | 31 | 是 | 否 | 未单列（它只能糊自身内容，不能糊背景；低版本静默无效） |
| AGSL `RuntimeShader` 折射 | **33** | 是 | 否 | ✅（只能作用于自身已渲染内容） |
| 窗口级 `setBackgroundBlurRadius` + `FLAG_BLUR_BEHIND` | **31** | 是 | 是（Dialog/浮窗） | ⏸ 移交另一路 |
| 超椭圆裁剪 / 边缘高光 / 内阴影 / 噪声 | 26（纯 Canvas） | 否 | 否 | ✅ |
| 降级假玻璃（半透明+渐变+噪声） | 26 | 否 | 否 | ✅ |

## 8. 性能（host GPU 模拟器实测，**真机未知**）

方法：`adb shell dumpsys gfxinfo dev.myco.android reset` → 背景持续滚动 + 玻璃动画 7 秒 → `dumpsys gfxinfo`。
（背景由单 Canvas 程序化绘制；玻璃=重绘背景 + RenderEffect。）

| 场景 | P50 | P90 | P95 | P99 | Janky(>16ms) |
|---|---|---|---|---|---|
| **基线**：无玻璃，只滚动背景 | 25ms | 34ms | 34ms | 48ms | 0.94% |
| 1 层玻璃（半径动画 6-40dp） | 31ms | 44ms | 48ms | 65ms | 3.93% |
| 2 层玻璃（半径动画 6-40dp） | 32ms | 44ms | 48ms | 65ms | 2.38% |
| 3 层玻璃（半径动画 6-40dp） | 32ms | 48ms | 48ms | 69ms | 3.14% |
| 1 层，固定 24dp | 31ms | 34ms | 36ms | 48ms | 1.18% |
| 1 层，固定 40dp | 32ms | 42ms | 46ms | 48ms | 1.18% |
| 1 层，固定 48dp | 28ms | 32ms | 34ms | 48ms | 0.95% |

读法：
- **模拟器本身就不是 60Hz 环境**：连"无玻璃"基线都是 P50 25ms（≈40fps）、P90 34ms。所以**本机数据只能做相对比较，不能当作真机帧预算**。
- 加玻璃后 P50 从 25ms → 31ms（**+6ms**），1/2/3 层差异在噪声范围内（31/32/32ms）——因为本机瓶颈在模拟器合成/呈现，不在 blur 本身。
- **半径 24/40/48dp 帧时间无可测差异**（28-32ms）→ 大半径不是主要成本；**主要成本是"每块玻璃每帧多画一遍背景"**。
- in-app Choreographer 读数稳定 16.0ms（vsync 节拍，UI 线程没掉帧），与 gfxinfo 的 31ms 不矛盾：瓶颈在合成/呈现侧，不在 UI 线程。
- **必须真机确认的三件事**：① 60/120Hz 下的真实帧预算；② API 31 的"陈旧模糊"（本机 API 35 未复现，`07/08` 两张图证明本机是跟手更新的）；③ OEM 的窗口模糊与省电策略。

## 9. 对 myco 元素的建议（**遵守 G-19：禁止"普通透明"，只有 A 不透明+neumorphism / B 真模糊+玻璃折射**）

G-19（`docs/spec/00-global-rules.md`，用户 2026-11-27 定死）：
- **A. 不透明 + neumorphism**：实体底色 + 凸/凹投影，用于常驻元素、卡片、列表、输入区、顶栏、设置页等。
- **B. 真背景模糊 + 玻璃折射**：真 backdrop 模糊 + 边缘折射/色散 + 镜面高光 + 内阴影，用于浮层，以及"动态成本验证过关"的常驻元素。
- **明令禁止**：半透明 + 无模糊的"普通透明"（含"低 tint + 高光"这种近似）。

> 因此本报告第一版的"半透明 + 高光"/"纯色"建议**作废**：负担不起真模糊的元素一律走 **A（不透明 neumorphism）**，不许退化成半透明。

| 元素 | 建议 | 理由 / 代价 |
|---|---|---|
| **输入区胶囊** | **A 不透明 + neumorphism**（凹槽输入框 + 凸起发送键）；仅当 `dynamic` 场景实测过关才升级 B（真 blur） | 常驻、叠在滚动列表上；每帧重绘背景在滚动时最贵。G-19 下不允许"半透明+高光"折中。 |
| **顶栏** | **A 不透明 + neumorphism**（与内容有明显分层投影）；滚动停止后再考虑 B | 常驻、覆盖面积大；滚动时 blur = 每帧全宽重绘。 |
| **抽屉 / sheet** | **B 真 backdrop 模糊 16–24dp + 低 tint + rim + 内阴影**（有 shader 时加边缘折射） | 瞬态、内容被遮住一半，成本可接受；24dp 下底层文字不可读但结构可辨，符合"浮层"语义。 |
| **modal** | **B 真 backdrop 模糊 24–40dp + tint 4–8% + 噪声 1.2% + 边缘折射** | 需要强隔离感；大半径让背景只剩余色块，不抢注意力。 |
| **toast** | **A 不透明 + neumorphism** | 短暂、小面积、可能叠在任意内容上；真模糊收益低。G-19 不允许半透明。 |
| **建议 chip** | **A 不透明 + neumorphism**（凸起 chip） | 小而密集，blur 会互相采样导致"脏"；文本可读性优先。 |
| **工具井** | **B 真 blur 16–24dp**（展开态），收起态走 A | 展开是瞬态；注意同屏玻璃 ≤3（§5）。 |
| 浮层里的模型/思考强度选择框（DSH 同款） | **B：blur 32–40dp + tint 4–8% + saturate 1.3–1.5**（有 API33 再加边缘折射） | 本机实测：该档"看不出模糊、但细节被柔化"，正是 DSH 观感（`10-subtle`）。 |

**先做哪 3 个**（按收益/风险/G-19 合规）：
1. **sheet / modal 的真 backdrop 模糊 + 玻璃边缘（rim + 内阴影 + 有 shader 时折射）**——最能体现"液态玻璃"，瞬态、性能可控；
2. **通用玻璃材质层**（rim 高光 + 内阴影 + 边缘折射，可复用）+ **通用 neumorphism 层**（A 路线的凸/凹）——两条路线各一套基础材质，所有元素复用；
3. **输入区/顶栏先落 A（不透明 neumorphism）**，等 `dynamic` 场景实测（每帧/隔帧/降分辨率）出来再决定是否升级 B。
## 10. 已知不可行 / 未验证

- ✅ ~~本机 `record + drawLayer` 捕获背景不可用~~ → **已修正**（§11）：`record(IntSize){}` 扩展可用，捕获路径成为主路径（一次捕获、N 块玻璃共享）。
- ❌ **AGSL 不能采样背景**：`RuntimeShaderEffect` 的输入是所在 RenderNode 的内容；只能在"已经重绘出来的背景"上做位移，作用是"伪折射"，不是真的折射背景。
- ❌ **`Modifier.blur()` 只能糊自身内容**，不能糊背景；API<31 静默无效（内容按原样渲染）。
- ⏸ **窗口级模糊未验证真伪**（已移交另一路）：`isCrossWindowBlurEnabled=true` 不代表画面糊；OEM/省电/视频播放都会让它静默失效。
- ⚠️ **API 31 "陈旧模糊"** 本机（API 35）未复现；`07/08` 两张图显示本机是跟手更新的，但**不能代表 API 31**。
- ⚠️ **真机性能未知**：本机是 host GPU 模拟器，P50 25ms 基线本身就超 16.6ms 预算；本报告不能证明真机 60Hz 能撑住"每帧多画一遍背景"。
- ⚠️ 重绘路径的适用边界：当前实验背景是"单 Canvas 程序化绘制"，重绘成本低；**换成真实列表/图片（LazyColumn + 网络图）后重绘成本会明显上升**，需在真机上用真实页面再测一轮。

## 11. 第二阶段结果（RCA 修正后的捕获路径 + target 复刻 + 动态 + 窗口模糊）

### 11.1 RCA 成立：捕获路径可用（证据）

- 根因：之前用 `GraphicsLayer.record(density, layoutDirection, size, block)` **成员函数**——它不重定向外层 canvas；改成 **`layer.record(IntSize(w,h)) { this@drawWithContent.drawContent() }` 扩展**（compose-ui 1.7.5 `DrawScope.kt:938-956`）后，内容真正进了层。
- 证据图：`20-rca-capture-verify.png`（t0）与 `21-rca-capture-verify-t3s.png`（背景滚动 3 秒后）：
  - 玻璃里是**模糊后的真实背景**（24dp 见到糊开的环/黄块色团；48dp 只剩色块）；
  - 背景滚动后玻璃内模糊内容**同步变化**（两图 hash 不同）→ 不是冻结帧；
  - 同屏 `repaint` 对照面板（强制重绘）与 capture 面板**同参数观感一致**；
  - logcat：`AGS​L 可用（液体折射着色器生效）`、无 AndroidRuntime 异常。
- 开关：`--ez glass_capture true` → 所有场景切成"源层录一次 / N 块玻璃共享一次捕获"；默认仍重绘，便于 A/B。

### 11.2 capture vs repaint（同场景同参数）

| 项 | capture（捕获） | repaint（重绘） |
|---|---|---|
| 质量 | 一致（20/21 与 33/27 对比） | 一致 |
| 每帧成本结构 | **1 次背景录制 + N 次 blur pass** | **N 次背景重绘** |
| 实测 P50（模拟器）1 块玻璃 | 28ms（`34`） | 28ms（`37`） |
| 实测 P50，13% 屏 2 块 | 28ms（`28`） | 29ms（`33`） |
| 实测 P50，整屏 1 块 | 29ms（`31`） | — |

> 模拟器基线本身 ~25ms，两种路径的差异**被模拟器合成开销掩盖**（差 0–1ms，在噪声内）。结构上 capture 随玻璃块数增长是 N 次 blur、repaint 是 N 次全背景重绘 → **块数越多 capture 越有优势**；但"真机能否 60fps"仍需真机验证。

### 11.4 边缘折射对照（`glass_scene=refraction`）

- `26-refraction-capture.png`（捕获路径，棋盘背景）：三块同背景面板——API33+ 液体 shader（边缘有明显位移/弯折 + 轻微彩边 + 镜面高光）、API31–32 无 shader（只有直亮边）、纯 blur（无高光）。折射贡献主要体现在**边缘 1–3dp 内的像素弯折**，中景几乎无差别。

### 11.5 动态（`glass_scene=dynamic`：顶栏 60dp + 输入区 100dp 玻璃，背景每帧滚动）

| 场景（capture 路径） | 玻璃面积 | 更新策略 | P50 | P90 | P95 | P99 | Janky |
|---|---|---|---|---|---|---|---|
| 基线（无玻璃） | 0 | — | 25ms | 34ms | 34ms | 48ms | 0.94% |
| `28` 顶栏+输入区 | ≈13% | 每帧 | 28ms | 44ms | 48ms | 81ms | 5.5% |
| `29` 仅顶栏 | ≈5% | 每帧 | 27ms | 32ms | 34ms | 48ms | 1.1% |
| `30` 仅输入区 | ≈8% | 每帧 | 27ms | 34ms | 34ms | 48ms | 1.4% |
| `31` 整屏玻璃 | ≈100% | 每帧 | 29ms | 34ms | 34ms | 48ms | 1.4% |
| `32` 顶栏+输入区 | ≈13% | 隔帧（层每 2 帧录一次） | 28ms | 34ms | 34ms | 48ms | 1.1% |
| `33` repaint 对照 | ≈13% | 每帧 | 29ms | 34ms | 34ms | 48ms | 1.4% |

读法：
- 本机所有组合都在 **P50 27–29ms**，差异在噪声内（模拟器基线 25ms）→ **在模拟器上无法区分"面积/策略"的收益**；只能说"没有额外劣化"。
- 13% 面积 + 每帧的组合 P90 偶尔到 44ms（janky 5.5%），是采样噪声而非稳定规律。
- **能否 60fps：本机不能回答**（模拟器基线已 >16.6ms）。结构上，capture 路径下每帧成本 = 1 次背景录制 + N 次 blur；**玻璃面积越大、blur 填充率越高**；隔帧更新（`recordEvery=2`）能省掉一半录制，但会让玻璃里的背景"跳帧"（观感可见轻微拖影）。
- 结论建议：**浮层（sheet/modal/菜单）用 capture + 每帧更新**；**常驻的顶栏/输入区若升级 B 路线，建议"滚动停止后启用、滚动中用不透明 neumorphism"**（既满足 G-19，又避免滚动时每帧重绘/录制）。

### 11.6 窗口级 blurBehind 动态测试

- `38-winblur-dyn-t0.png` / `39-winblur-dyn-t3s.png`：全屏**透明 overlay Dialog** + `FLAG_BLUR_BEHIND` + `setBackgroundBlurRadius(40dp)`，背后彩色列表每帧滚动。

## 12. G-21 合规版：干净玻璃测试体（物理折射）

### 12.1 原则与实现

G-21：**要么真效果，要么明确说"结构不允许"并换路径；禁止任何"看起来像"的近似。** 参考图只传达质感方向，不是几何复刻目标。

`glass_scene=physics`（别名 `target` 已指向它）删除了第一版的全部非物理装饰：外圈光晕、径向渐变"镜头"、月牙、文字图标、任何渐变/光斑。玻璃体是**无装饰的圆角矩形**，只保留能从公式算出来的东西：

| 项 | 计算方式 |
|---|---|
| 真背景模糊 | 捕获层（`record(IntSize){}` 扩展）+ `RenderEffect.createBlurEffect` |
| 真像素位移折射 | `uv += sdfNormal(p) * f(distToEdge) * refractPx`，`f = smoothstep(bandPx, 0, distToEdge)` → **只在边缘带非零** |
| 边缘法线 | 圆角矩形 SDF 的数值梯度（±0.75px 差分） |
| 色散 | R/B 采样点沿法线反向偏移 `±dispPx * f`，G 不偏 |
| 镜面高光 | `pow(max(dot(N, L), 0), 4) * thin(distToEdge) * rim`，L = 固定光照方向 (-0.75,-0.66) |
| 内阴影 | `smoothstep(14,0,distToEdge) * (0.35+0.65*back) * shadow`，back = 背光侧权重 |
| tint | 唯一的产品参数（均匀白 alpha），不做任何渐变 |

参数滑杆（截图用 `glass_ui=false` 隐藏）：**refract 强度(dp) / 边缘带宽 band(dp) / 色散 disp(px) / 高光强度 / 模糊半径 / tint**。

### 12.2 验证：`refract=0` vs `refract=3dp` 的像素级 diff

命令（除 refract 外参数完全一致、背景静态）：

```bash

adb shell am start ... --es glass_scene physics --ez glass_capture true --ez glass_ui false \

# B 同上，--ef glass_refract 3
```

- 图：`40-physics-refract0.png` / `41-physics-refract3dp.png` / `42-physics-refract3dp-disp2.png`（色散加大）
- **像素 diff 图**：`43-diff-refract0-vs-refract3dp.png`（洋红 = 变化像素，放大 8 倍；压暗原图为底）
- diff 统计（脚本：`_ws/out/glassdiff.ps1`，输出 `_ws/out/glassdiff-result.txt`）：

**实测结果（host GPU / API 35，`_ws/out/glassdiff.ps1` 逐像素计算）**：

| 指标 | 数值 |
|---|---|
| 变化像素 / 全图 | **16,546 / 2,419,200 = 0.68%** |
| 变化外接框 | **x=103..976, y=903..1296（874×394）** —— 恰好是玻璃体本身（一个薄环） |

- 变化环的最大通道差 47，出现在边缘（"背景被弯折"），整块没有整体变亮/发光（若是滤镜/加亮，变化会铺满整块）；
- 色散（disp 1→2px）同样只在边缘带内变化（0.13%），内部零变化；
- 观感差异是"边缘被弯折 + 极薄几何高光/内阴影"，玻璃体干净（无光晕、无径向渐变、无图标装饰）。

### 12.3 结构不允许（明确不做，不用近似凑）

- ❌ **「镜头内背景放大」这类局部透镜效果** —— **结构不允许**：
  - 屏幕空间里我们只有**一张 2D 背景图**，没有任何深度/入射光线信息；真正的折射需要"玻璃另一边被弯折的光线在哪里"这个 3D 信息（需要 3D 场景/光线追踪，或从另一个视角做环境捕获）。
  - 在 2D 采样里做"以某个点为中心放大"本质是**参数化的采样 warp（缩放映射）**，不是从数据算出来的物理量 → 按 G-21 属于"看起来像"的近似，**不做**。
  - 能做到的边界就是本节的**边缘带位移**：法线方向、`distanceToEdge` 决定强度，这是从 SDF 数据直接算出来的几何量。
- ❌ **外发光/光晕**：参考图没有（上一轮判读错误已撤回）；即使有，也需要真正的 blur 外发光，不能用描边近似 → 不做。
- ❌ **镜头/图标/文字装饰**：属于 UI 内容，不属于玻璃材质；需要时作为上层普通内容绘制，不参与玻璃计算。

### 12.4 API 门槛（物理版）

| 能力 | 最低 API | 备注 |
|---|---|---|
| 真背景模糊（捕获 + BlurEffect） | 31 | 需要硬件加速 |
| 边缘位移折射 / 色散 / 法线高光 / 内阴影 | **33**（AGSL RuntimeShader） | API 31–32 **只能做模糊 + tint**（无折射、无几何高光/内阴影），差异见 §11.4 |
| 捕获层 `record(IntSize){}` | 29（Compose 1.7.5 实现） | 本机验证可用 |

### 12.6 推荐固化参数（从 physics 场景推出，供 M5 材质 token）

| token | 值 | 理由（可判断） |
|---|---|---|
| `blur` | **24dp**（浮层）；modal 32–40dp | 24dp 下背景只剩色块/明暗但仍能辨位置；再大用于强隔离的 modal。本机半径 24/40/48 帧时间无差异（§8） |
| `tint` | **4% 白** | 2% 太"生"（背景色过冲），8–10% 明显发白；4% 保留透明感且文字可读（`41`/`44` 可直接对比） |
| `refract` | **3dp** | `43` 证明 3dp 时变化只落边缘环、内部零变化；1dp 几乎看不出，6dp（`24` 时代）边缘过冲 |
| `band` | **6dp** | 6dp 时折射带宽度与 3dp 位移匹配；band 过大会把"内部"也拖进变化区（违反 G-21 判据） |
| `dispersion` | **1px** | `42`/`48`：2px 在 1080p 已偏"花"；1px 只留极轻彩边 |
| `rim（几何高光）` | **35%** | `41` 的薄边高光来自 `dot(N,L)`，35% 有"玻璃边"但不发白；>60% 开始像塑料 |
| `innerShadow` | **25%** | 由 `distToEdge` 推出的边缘暗化，25% 给出厚度感又不压暗内容 |
| `corner` | 26dp（卡片）/ 胶囊 r=h/2 | 形状参数，与折射无关 |

**API 31–32 结论（`44`）**：只有 blur + tint 时**"还能看"，但缺少玻璃标识**——边缘是软过渡、没有薄高光/内阴影，视觉上更像"磨砂面板"而不是玻璃。且按 G-21 不能用描边/渐变去补这个边缘（不属于几何/物理可算项）。**建议：API31–32 的浮层直接走 A 路线（不透明 neumorphism），不要在 31–32 上启用"裸 blur+tint"玻璃。**
