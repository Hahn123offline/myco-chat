# M5 功能审计计划（暂缓全量逻辑迁移，2026-11-27）

> 用户决定：**先放缓具体逻辑的全量迁移**，主要精力先把 UI 布局在不同状态下调对；随后用「参考仓库 + 旧代码」做**精确到每一个可点击按钮**的功能需求审计，用户按已有实现逐项核对，确保一行功能不漏。

## 1. 为什么暂缓

当前逐轮"发现丢了什么再补"的效率太低：旧 `ChatScreen`/`ChatMessages` 里的交互（滚动阻挡、展开状态、工具展示、分支、菜单、附件、错误态…）散落在 `MainActivity.kt` + `ChatContent.kt` 约 3,800 行里，靠增量迁移必然漏。

## 2. 审计方法（下一阶段）

1. **静态盘点**：对旧实现做 AST/文本盘点，列出所有可点击/可交互元素：
   - `Modifier.clickable` / `combinedClickable` / `pointerInput` / `TextButton` / `Button` / `IconButton` / `ListItem` / `FilterChip` / `Switch` / 长按 / 滑动 / 返回；
   - 每个记录：入口函数、所在界面、触发条件、依赖状态、调用命令。
2. **参考仓库对照**：chat-demo（DSH 官方 demo）、deepseek-api-app、RikkaHub、DSH Go —— 用于补"我们没做但业界都做"的交互（如消息长按菜单项、工具卡展开层级、来源 Sheet 截断提示）。
3. **逐项需求表**：每行 = 一个可点击元素 → 期望行为 → 旧实现证据（文件/行）→ M5 状态 → 验收方式。用户逐项核对"要不要 / 对不对"。
4. **验收**：每项都留真机截图/录屏，用户确认后打勾，未确认不删旧实现。

## 3. 现阶段优先：UI 状态矩阵

在审计前，先把 M5 聊天页在**不同状态下的布局**调正确（数据可静态/真实混合）：

| 状态 | 要看什么 |
|---|---|
| 空会话 | 输入区位置、空态文案/图标 |
| 正常对话 | turn 间距、用户气泡宽度、正文行高 |
| 思考中（折叠） | 动态最后一行 + 呼吸点、不跳行 |
| 思考中（展开） | 组级高度上限 + 内层滚动、到边交给外层 |
| 工具运行/完成 | 工具块（参数/来源/结果）、失败态 |
| 流式正文 | 光标位置、跟随底部、停止态 |
| 长回答 | 滚动性能、回到底部按钮 |
| 分支 | `‹ 1/2 ›` 位置与切换后锚点 |
| 错误/中断 | 错误条、重试入口 |
| 附件 | 待发送预览、发送后展示 |
| 深浅色 | 玻璃/阴影/文字对比 |
