## Q-03 移动端命中区怎么放大（✅ 已取证，几何约束已算出，待你选）

**参考实现的实际做法**（`ref/dsh-mobile.md` §4，E0）：
- 手机适配层一律 `min-height:44`（菜单/导航/输入/按钮，`client.js:524-538,770,894-905`）；
- 视觉不能改的（开关 20px 高）用伪元素 `::after{inset:-12px -8px}` 扩边；
- **字号 stepper 因两个箭头中心距只有 14px，扩边必然重叠，只能重排成并排 44×44 + gap2**（`client.js:802-865`，issue #2 的根因）；
- 扩边**没有任何相邻隔离声明** → 相邻设置行各侵入 12px，重叠带最大 24px（这是它的缺陷，不要抄）。

**几何硬约束（我算的，基于 E0 尺寸）**：DSH 折叠行视觉高 `24px`、过程组行距 `6px`
（`ReasoningRow.module.css:6-9`、`ChatView.module.css:72-84`）。相邻两行各向下/上扩 `e`，
要求不重叠则 `2e ≤ 6` → **命中高最多 30px**。要做到 44dp 需 `e = 10` → **必然重叠 14px**。

**三条出路，必须选一条**：

| 方案 | 做法 | 代价 | 适用 |
|---|---|---|---|
| **A. 只让"标题+箭头"响应点击** | 摘要区不响应点击；标题做成 44×44 命中盒（视觉不变，热区向左/上扩，行距不再受限） | 用户点摘要无反应，需要学习成本；命中率取决于"标题"是否明显 | 最省视觉代价 |
| **B. 行距改 ≥20px** | 过程行上下各留 10px 空白 | 过程区垂直空间多用约 2.3 倍，一屏能看的过程行变少 | 过程区本来就要折叠，可接受 |
| **C. 视觉直接抬到 44dp** | 整行 44dp | 过程行密度约 −40%，思考/工具区会更"胖" | 最省事、最符合平台直觉 |

**已固化为规则**：[G-11 命中区契约](00-global-rules.md) 给出了三条判定式
`h+2e≥F ∧ 2e≤g ∧ g−2e≥B`，以及降级顺序（先加行距 → 再"关键区可点"→ 最后才抬视觉高），
并禁止"硬扩边导致命中盒重叠"。

**我的建议**：**A + B 组合**——标题行做到 `F` 命中（方案 A），同时把过程组内行距从 6px 提到 `≥20px`
（方案 B 的弱化版，此时 `2e≤20` 允许 `e=10`）。这样视觉密度只降一点，且几何成立。

**仍需你拍的一点：`F` 取 48dp 还是 44dp？**
- `48dp`：Material/Android 规范 + 旧 myco `TextButton` 默认值（**E0**）。代价是过程行节距 30→56dp、密度约 −46%。
- `44dp`：WCAG 2.5.5 最低线。代价略小，但偏离 Android 平台惯例，且旧 myco 现成控件是 48。
- 我的倾向：**48dp**（平台一致性 > 省 4dp），只在确实挤不下的并排小目标上用 44dp。

## Q-08 ⚠️ G-04 与 DSH 真实实现相反（✅ 证据已补全，待你一句话）

**DSH 侧「允许滚链」是刻意的，不是漏做**（`ref/dsh-chat.md` §0-3 + 补证）：
1. `interrupt` 回调**不接收事件对象**（`use-process-scroll.ts:53-56`），结构上不可能 `preventDefault`；
2. 外层会话监听**主动 passive**（`use-chat-viewport.ts:46-47,78-80`）——规范上就放弃了阻止能力；
3. `ui-chat/src` 全目录 `preventDefault` 命中为 0；
4. 同库分轴惯例：横向 `contain`、纵向 `auto`（`JsonTree.module.css:16-17`、`MarkdownText.module.css:195`）；
5. 轮次导航轨道**明写** "no scroll chaining" + `contain`（`TurnNavigator.module.css:48-56`）；
6. README 把它写成规格句（`conversation-nodes/README.md:182`，E1）。

**建议**：拆成两条规则——`G-04a 触摸惯性到边吸收`（移动端，你的口径，全量生效）/ `G-04b 滚轮可链式`（桌面，DSH 口径）。
我的判断：这不是对错，是输入设备差异；手机上没有滚轮，等于 G-04 原样保留。

**需要你一句话**：同意拆成 a/b（我推荐）/ 统一按 G-04 全量禁止 / 统一按 DSH 允许链式。

## Q-05 过程组封顶上限取多少 —— ✅ 已取证，待确认换算

**DSH 真实值（E0）**：`max-height: min(400px, 50vh)` + `scrollbar-gutter: stable`
（`dsh ChatGroupSeat.module.css:86-92`）；展开态（running 轮 / Verbose）**整个封顶被移除**
（`:135-139`）。到边渐隐 = **上下各 24px 的 mask 渐变**，两端同时可滚时合并成四段渐变，
判定阈值 1px（`:101-117`、`ChatGroupSeat.tsx:182-184`）——**不是高度参数、不是 opacity 参数**。
组内行距 6px，assistant 回复前后 12px，turn-process 与内容 16px（`ChatView.module.css:72-84,111-116`）。

**我的旧值作废**：屏高 45% / ≤360dp 是 E2。

**仍需你拍的一点**：`min(400px, 50vh)` 是 CSS px，直接搬到 Compose 会用 dp。
手机上 50vh≈400dp，两者几乎相等（≈400dp）；但**平板/横屏**下 400dp 会显得很矮、50vh 很高。
建议：**手机 = 50vh（≈400dp）；宽屏 = min(400dp, 50vh)**，即保持 DSH 语义
「小屏听比例、大屏听绝对值」。同意的话我写进 `panels/chat.md`。

**必须一起抄的细节**：`scrollbar-gutter: stable`（否则「内容刚好超一屏」时横向跳 8–15px）。
Compose 里等价物 = 内滚容器预留滚动条宽度，需在 spec 里写死。

## Q-07 "回到底部"还是 DSH 式轮次导航 —— ✅ 已取证，两者并存

**DSH 真实形态（E0）**：

| 层 | 形态 | 出现条件 | 证据 |
|---|---|---|---|
| 回到底部 | 34×34 圆形 overlay 按钮，右下角 16px（宿主滚动时再抬 `--dsh-composer-height`），z-index 8 压在输入卡上方 | **仅当不跟随时才渲染** | `ChatView.tsx:240-251`、`ChatView.module.css:244-294` |
| 轮次导航 | 右侧 28px 竖条，**10px 定距**刻度（20×2px），hover/focus 出预览卡（1 行 prompt + 3 行 response），虚拟滚动 + 24px 两端渐隐，`overscroll-behavior: contain` | **容器宽 ≤900px 直接 `display:none`**（移动端没有） | `TurnNavigator.tsx:29-33,110-177,227-281`、`TurnNavigator.module.css:26-46,50-78,207-211` |

**跟随判据是「距离」不是「方向」**：距底 ≤25px 视为贴底跟随；读者移动且距底 >1px 立刻停跟随
（500ms 采样定时器）；回到距底 <1px 立即恢复。跟随中会话位置**存 null**（语义位置）而非像素
（`use-chat-reading.ts:7,134-144,186-192,218-234`、`use-scroll-follow.ts:67,90-95`）。

**建议**：保留 v 钮（与现状一致，语义正确），**手机端不加轮次导航**（DSH 自己也不给），
宽屏/平板再加轨道层。需要你确认"何时算宽屏"（建议 ≥900dp，与 DSH 对齐）。

## Q-09 失败态要不要「重试按钮」

- **事实（E0）**：DSH 三处失败态（`turn-error` / `turn-max-tokens` / 自动重试）**都没有重试按钮**；
  自动重试是倒计时展示，失败是纯说明。
- **冲突**：myco 现有错误条有重试入口（用户之前也要求过）。
- **建议**：保留 myco 的重试按钮（移动端网络不稳，手动重试是刚需），
  但需确认：**重试 = 重发上一条 / 重新生成该回复 / 两者分开放**？这是交互歧义，必须你定。

## Q-10 消息操作条在手机上要不要常驻

- **事实（E0）**：DSH 操作条 28×28 图标，桌面默认 `opacity:0` 但**仍占位**，
  hover/focus 才显现；触摸设备因不进 `@media (hover:hover)` 而**全部常驻可见**，
  且**没有长按唤出**（`MessageIconActions.module.css:5-10,42-61,63-87`）。
- **待确认**：myco 手机端照抄"常驻可见"吗？常驻会更像工具条、但每条消息下多一行；
  另一种是默认收起、点气泡/长按唤出。
- **附**：DSH 分支按钮不可用时**故意不用原生 disabled**（因为 Tooltip 需要 hover/focus 事件），
  这个取舍在移动端不成立（无 Tooltip），可以简化。
