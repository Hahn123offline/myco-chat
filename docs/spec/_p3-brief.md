# P3 任务书：把 P2 合并稿变成可实现的「面板规格」

> 用法：Lead 给每个面板派一个写手，先读本文件 + 指定输入，只写 `docs/spec/panels/<panel>.md`。
> P3 的产物是 **P4 实现的唯一依据**：实现时不许再看 `ref/`，只看 `panels/`。

## 你的角色

你是面板规格写手。P2 已经把「参考实现怎么做 + 我们选哪个」拍完（`p2/*.md` + `decision-pack.md` §6 的 D-01…D-20）。
你**不再做选择**，只做三件事：
1. 把拍板结果**翻译成可实现的布局与交互**（线框、网格、状态矩阵）；
2. 把每个节点写成 **13 字段**（照 `schema-node.md` 的格式），字段 12 写「依据」= 拍板编号 + 证据行；
3. 给每个可验收行为分配 **稳定验收 ID**，写清判定方式。

## 必须读

1. `docs/spec/_p3-brief.md`（本文件）
2. `docs/spec/schema-node.md`（13 字段定义 + 金标准样本，**格式照抄**）
3. `docs/spec/00-global-rules.md`（**全部** G-00…G-18，这是硬约束）
4. `docs/spec/decision-pack.md` **§6 决策记录**（D-01…D-20 已拍板结果）+ §1 的选项描述（理解拍板含义）
5. 你负责面板对应的 `docs/spec/p2/<panel>.md`（合并稿：节点清单、对照表、补充项、明确不做、待确认）
6. 必要时回查 `docs/spec/ref/*.md` 取精确数值（**只在需要数值/证据行时查，不要重读全文**）

## 输出结构（严格）

```
# 面板规格：<panel>

## 0. 一句话 + 范围
（这个面板负责什么、不负责什么、与相邻面板的边界）

## 1. 布局与网格
- ASCII 线框（至少 3 个状态：空/常态/极端内容）
- 网格表：行/列/间距/内边距/最小宽度/最大宽度，全部用 dp
- 与容器的关系（在 M2 覆盖栈里的位置、返回语义、insets）

## 2. 状态矩阵
| 状态 | 进入条件 | 布局变化 | 视觉 | 可交互项 | 退出 |

## 3. 节点规格（13 字段，每个可点/可滚/可展开节点一节）
### <node.id> — <一句话>
| # | 字段 | 内容 |
| 1 | 身份与出现条件 | ... |
| ... | ... | ... |
| 13 | 反证 + 验收 ID | ... |

## 4. 验收清单
| ID | 判定 | 方式（真机/截图/单测） | 依赖 |
（ID 格式：<PANEL大写>-<两位序号>，如 CHAT-01；全局前缀见 §验收 ID 分配）

## 5. 待确认（若有）
| ID | 问题 | 两解与后果 |
（P3 阶段若发现 P2 遗漏的决策点，**必须写在这里并标阻塞**，不许自行决定）
```

## 硬规则（违反即不合格）

1. **不许重新讨论已拍板项**（D-01…D-20）。若发现拍板与证据冲突，写进 §5 并标注「与 D-xx 冲突」。
2. **不许推测**：每个数值要么来自 ref/ 的 `path:line`，要么来自 G 规则，要么标「我方取值（P4 真机校准）」并给出理由。
   **E2 推测不得出现**。
3. **每个节点必须有**：唯一 ID、13 字段、证据/拍板来源、反证、至少 1 个验收 ID。
4. **状态矩阵必须覆盖**：空、加载、正常、长内容、失败、禁用、深色、大字号、横屏/宽屏。
   不适用的写「不适用 + 原因」，不许省略。
5. **验收 ID 必须可判定**：写"点开正常"不合格；写"展开后头部 y 坐标不变（±1dp），向下滚 3 屏仍可点收起"合格。
6. **明确不做**：把 P2 §4 的「明确不做」搬进本文件 §0 末尾一行摘要（不逐条展开），避免实现时"顺手做了"。
7. 只写你自己的一个文件，不改 `p2/**`、`ref/**`、规则、决策包、其它 `panels/*.md`；不改 app；不 commit。
