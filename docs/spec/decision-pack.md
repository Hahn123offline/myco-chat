| D-51 | `/` 候选面板用 **Popup 独立窗口**；outside-tap 关闭列入"接线后必验项" | in-flow 外浮层会被父边界裁剪；先跑通再评估改回 overlay |
| D-52 | 同帧高度采用**选型 A（TextMeasurer 解析式 + SideEffect 发布）**；真机出现 1 帧差再升级为自定义 Layout | 先用最小实现验证；升级触发点已写进 P3-CMP-07 |
| D-53 | 失败图片点击**打开灯箱**（而非只靠文件卡重试），以保留唯一移除入口 | 失败态也要能删掉，否则卡死在轨里 |

### 6.13 玻璃/模糊的产品标定（D-54…D-56）

| ID | 决定 | 依据 |
|---|---|---|
| D-54 | **真背景模糊只用于层叠浮层**（抽屉 / sheet / dialog / menu / 灯箱），**不用于滚动内容上方的常驻元素**（顶栏、输入区） | 用户实机观察：DSH 手机端只在子智能体列表与模型/思考强度对话框有模糊，都是浮层；浮层打开时下层静止 → 重绘背景成本低；滚动内容上方每帧重绘成本高 |
| D-55 | **取向："更清晰的透明感"优先，磨砂面板作为可选项**；参数方向 = **大半径 + 低 tint + 适度饱和度提升**（DSH 为 `blur(40px) saturate(150%)`） | 用户原话：模糊"几乎看不出来但对细节加分"；要的是透明感而不是遮挡 |
| D-56 | 具体半径/tint 由玻璃实验室的 `subtle`/`clarity` 两组对照 + 半径-帧时间表决定，**不进 P4 实现前不写死数值** | 效果与性能的取舍需要数据，不靠猜 |

### 6.14 折射与"动态"问题的裁定方向（D-57…D-59，待实验确认）

| ID | 事项 | 方向 |
|---|---|---|
| D-57 | **边缘折射可做**：在"重绘背景"路线上，重绘出的背景属于我们自己内容 → AGSL `RuntimeShader`（API 33+）可对其做边缘采样偏移 + 色散 + 镜面高光 + 内阴影，即"清澈 + 边缘凸起折射"。**API 31–32 无 shader**，只能做边缘高光+内阴影的近似 | 由 `scene=refraction` 实验确认观感与帧成本 |
| D-58 | **"只在静态场景划算"的说法不成立**（用户指出磨砂优势在动的时候）→ 必须实测**动态**：滚动列表在玻璃下方时，模糊跟手更新的成本（全帧/隔帧/降分辨率），以及"只重绘玻璃区域"的面积-成本关系 | 由 `scene=dynamic` 实验给出 60fps 可行性 |
| D-59 | **窗口级 blurBehind 是"动态真模糊"的潜在最优解**：系统合成器做模糊、自动跟随背景滚动、成本极低；但受 OEM/省电静默关闭与窗口交互复杂度限制。必须实测"背后列表滚动时 blur 是否实时更新" | 若成立，顶栏/输入区这类常驻元素优先走窗口方案 |

### 6.15 视觉路线定死（D-60…D-62，用户 2026-11-27）

| ID | 决定 | 影响 |
|---|---|---|
| **D-60** | **禁止普通透明**。只有两条路：**A 不透明 neumorphism** / **B 真模糊+玻璃折射**（见 G-19） | 作废此前"半透明+高光"的所有建议（含 D-54 里顶栏/输入区的方案） |
| **D-61** | 负担不起真模糊的位置（滚动内容上方、低端机、API<31）**一律走 A 不透明 neumorphism**，不许退化成半透明 | 输入区/顶栏默认 = A；只有动态模糊成本验证过关才允许升级为 B |
| **D-62** | 视觉目标 = 用户参考图 `docs/reports/assets/reference/glass-target-focus-pill.jpg`：胶囊 + 背景色渗出 + 边缘折射/色散 + 沿边高光 + 内阴影，**清晰而非磨砂乳白** | 玻璃实验室下一阶段以"复刻这张图"为第一优先 |

### 6.16 机制翻案：真背景模糊在 1.7.5 上可行（D-63…D-65）

| ID | 决定 | 证据 / 说明 |
|---|---|---|
| **D-63** | **推翻此前"本机不可用"的结论**：`rememberGraphicsLayer` + **`DrawScope.record {}` 扩展** + 兄弟节点 `drawLayer` + `RenderEffect` **在本栈（Compose 1.7.5 / Kotlin 2.0.21）可用** | RCA：我们用了 4 参数**成员函数** `layer.record(density, layoutDirection, size, block)`，它不重定向 canvas → 层为空；改成 2 参数**扩展** `layer.record(IntSize) { drawContent() }` 即可。源码：`compose-ui 1.7.5 DrawScope.kt:938-956,317-354`；Haze 1.1.1 同版本组合（E0） |
| **D-64** | **主路径 = 捕获（capture）而非重绘（repaint）**：静态浮层源层只录一次，N 块玻璃共享一次捕获；动态场景每帧录一次源层 | 调研：降采样收益很小（Haze inputScale=0.5 只降 5%），真正有效的是"共享一次捕获 + 缓存层/effect + 静止背景只录一次" |
| **D-65** | 保留 **repaint 作为对照组/兜底**（用于验证与极端降级），但产品默认走 capture | 需要一组同场景同参数对照（质量、帧时间）来确认 |

### 6.17 RCA 已实机验证（D-66，推翻此前"不可用"结论）

| 项 | 结论 |
|---|---|
| 验证场景 | `glass_scene=capture`，host GPU（AMD 890M / GLES 3.1）API 35 |
| 证据 | `docs/reports/assets/glass/20-rca-capture-verify.png`（t0）、`21-rca-capture-verify-t3s.png`（3 秒后滚动） |
| 判据 | ① 玻璃内是**模糊后的真实背景**（非 tint 错觉，48dp 档只剩色块）；② **滚动时跟随更新**（t0→t3s 内容变化）；③ 同参数 **capture 与 repaint 观感一致** |
| 结论 | **真背景模糊在本栈（Compose 1.7.5 / Kotlin 2.0.21）完全可用**，修复只是 `DrawScope.record` 扩展 vs 成员函数一行之差 |
| 主路径 | **capture**：源层录一次 → N 块玻璃共享 → 各自 blur pass；静态层只录一次，动态层每帧录一次 |
| 成本预期 | 静态浮层远低于 repaint（不再每块重绘背景）；动态场景 N 块共享一次捕获 |

### 6.18 玻璃主路径与参数定稿（D-67…D-69，待用户选定档位）

| ID | 决定 | 内容 |
