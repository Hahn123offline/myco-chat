## G-01 浮层不占位（铁律）

**规则**：回到底部、FAB、Snackbar、悬浮提示一律 overlay 渲染，**不参与布局流**，
不产生高度、不推挤内容、不触发空行。

**为什么（反证）**：一旦占位，滚动到底部时列表高度突变 → 内容跳动；
用户正读到一半会被推走；且"回到底部"按钮本身变成遮挡物，
用户为了看到它下面那段必须再滚一下。用户已实际踩过：v 圆钮曾占整行。

**证据**：`user`（明确要求"悬浮在消息列表右下角，不再占布局高度"）；
`myco` commit `16d87df`/`bc99cbe`。

**违反症状**：出现一条横向空带、按钮随列表滚动、滚到底时画面顿跳。

**边界（必须遵守）**：G-01 **只约束 overlay**（回到底部、FAB、Snackbar、悬浮提示、菜单浮层）。
它**不约束**：① 参与布局的列（右栏、侧栏轨道，见 C-19）；② 内联状态条（连接指示器、上传进度条）；
③ 页面内的固定头/固定尾（输入区）。这三类**本来就占位**，判据是"它是否参与布局流"，
而不是"它看起来像不像浮层"。

## G-02 折叠行定高 + 兄弟零重排（硬约束）

**规则**：可折叠行折叠时必须是**固定高度**，并对该行启用尺寸隔离
（Web: `contain: size layout`；Compose: 固定 `height` + `Layout` 不测量子内容）。

**为什么（反证）**：折叠行的展示内容（摘要文本、呼吸点、工具名）是**流式变化**的；
若不隔离尺寸，摘要每变一次，整条消息里它下面的所有兄弟节点都会重排 →
用户正在读的正文上下抖动。这不是"动画不好看"，是**根本没法读**。

**证据**：`dsh` `packages/client/ui-chat/src/client/chat/ReasoningRow.module.css:6-9`

```css
.root:not([data-expanded]) {
  contain: size layout;
  height: calc(24px + var(--dsh-content-font-delta, 0px));
}
```

**违反症状**：思考中摘要逐字出现时，正文/工具块跟着上下跳；
折叠行展开收起后，其下方内容出现 1–2px 累积错位。

## G-03 展开三形态（硬约束，禁止混用）

**规则**：任何"可展开"节点必须先声明它属于哪一种，三选一：

| 形态 | 高度 | 谁滚 | 折叠时兄弟 | 适用 |
|---|---|---|---|---|
| **A. inline-uncapped + sticky header** | 不封顶，随内容长高 | 外层会话 | 被推挤 | 思考行（ReasoningRow） |
| **B. capped-inner-scroll** | 封顶，内层滚 | 内层优先，到边交给外层 | 被推挤（封顶后） | 过程组 / 工具组（process group） |
| **C. sheet-overlay** | 浮层，独立高度 | 浮层内 | 完全不占位 | 详情、来源、附件预览 |
| **D. state-switched**（D-11 新增） | 按状态切换：流式期走 B（封顶内滚+跟尾），定稿后走 A（不封顶） | 流式期内层，定稿后外层 | 随状态 | 思考/过程组在手机上 |

**为什么（反证）**：混用会互相破坏意图——
- 把 A 做成 B：思考内容被截断在一个小窗口里，用户永远读不完，且内滚与外滚打架（旧 myco 就是）；
- 把 B 做成 A：长工具输出把整个会话拉成几十屏，回到底部按钮几乎永远可用；
- 把 C 做成 A/B：详情抢走正文位置，用户退回时丢失阅读锚点。

**证据**：`dsh` 两类实现并存，且**不是同一个组件**：
- A：`ReasoningRow.tsx:70-74`（展开直接塞完整 Markdown，无高度限制）+
  `ReasoningRow.module.css:15-22`（展开时头部 `position: sticky; top: 0`）；
- B：`use-process-scroll.ts:1` 文件头注释
  *"Capped process-group scrolling and fades over the shared follow controller."*
  + `:48` 用 `canScrollUp/canScrollDown` 计算边缘渐隐。

**违反症状**：思考链读不完、滚动"卡在中间某处"、或整页被一段工具输出撑爆。

## G-04 内滚到边停住，不传残余速度（铁律）

**规则**：手势在一个内滚容器里到达上/下边缘时，**吸收掉剩余拖动/惯性**，不把速度传给外层；
只有当用户**在边缘继续施加新的手势**时，才允许外层接管。

**为什么（反证）**：用户明确给出——"那样用户就没法稳定地看自己想看的块，整个页面会乱滑，
软件没能成功猜测用户的操作意图从而让用户感到挫败。" 即：
一次手势 = 一次意图；意图在内层完成时被外泄，等于软件擅自改变了作用对象。

**证据**：`user`（明确拍板）。E0 代码证据待补：`dsh` 的
`use-scroll-follow.ts` / 浏览器 `overscroll-behavior` 具体实现（P1 补齐后升级本条）。

**违反症状**：展开过程组里往上滑，到头后整个会话开始滚动，读者丢失位置。

## G-05 流式边缘用遮罩渐隐，不用省略号

**规则**：流式追加中的单行摘要，右端用 `mask-image` 渐隐（Web）/ alpha 渐隐（Compose），
**不用 `text-overflow: ellipsis`**。

**为什么**：省略号是"内容到此结束"的语义；流式文本并没有结束。渐隐表达"还在长"，
且不会因省略号位置跳变产生视线跳动。

**证据**：`dsh` `ReasoningRow.module.css:59-66`

```css
.summary[data-streaming] { mask-image: linear-gradient(to right, black calc(100% - 48px), transparent); }
.summary[data-streaming] .summaryText { overflow: visible; text-overflow: clip; }
```

**违反症状**：思考中摘要显示 "…"，看起来像已经结束。

## G-06 展开态头部 sticky（硬约束）

**规则**：inline-uncapped 形态展开后，**头部（折叠开关那一行）吸附在会话视口顶部**，
背景用页面底色遮住下方内容。

**为什么（反证）**：展开的思考/正文可能比屏幕长得多；若头部随内容滚走，
用户想收起时已找不到入口，只能一路滚回顶部 —— 多屏内容下等于**无法关闭**。

**证据**：`dsh` `ReasoningRow.module.css:15-22`

```css
.root[data-expanded] [data-open] [data-disclosure-header] {
  position: sticky; top: 0; z-index: 1; background: var(--dsw-alias-bg-base);
}
```

**违反症状**：展开长思考后，只能滚到最上面才能收起。

## G-07 展开状态随轮次版本重置

**规则**：每个可展开节点的 open 状态是**本地状态**，绑在一个"版本号"上；
当所属轮次被隐藏/重建（版本前进）时，自动回到折叠。

**为什么（反证）**：若不重置，重新进入/重建的那一轮会带着上一轮的展开状态出现
（用户看到自己没展开过的块是展开的）；若不做版本绑定而直接全局存，
则同一轮的多个块会互相串状态。

**证据**：`dsh` `use-disclosure.ts:11-20`

```ts
const expanded = expandedVersion === version   // 版本前进 → 自动折叠
const toggle = () => setExpandedVersion(p => p === version ? null : version)
```

**违反症状**：切换分支/重进会话后展开状态错乱；或展开 A 导致 B 也展开。

## G-08 运行态必须有 a11y 文案

**规则**：任何"运行中/生成中"的视觉指示（呼吸点、shimmer、动画）必须配一段
屏幕阅读器可见（视觉隐藏）的文案。

**证据**：`dsh` `ReasoningRow.tsx:84`

```tsx
{running && <span className={a11yCss.visuallyHidden}>{t('row.running')}</span>}
```

**违反症状**：TalkBack 用户完全无法知道还在生成。

## G-09 行内层级 = secondary，一档低于正文

**适用范围（M3 收紧）**：本规则只适用于**过程成员行**（思考行、工具行、组头）的标题/摘要/流式摘要。**不适用于**过程组标题之外的正文、以及 DSH 过程组标题本身（DSH 过程组标题用正文字号 14pt，`ChatGroupSeat` 节点 E0，与本规则的 secondary 相冲突 → 以"过程成员行"为界，组标题按正文处理）。

**规则**：折叠行标题/摘要、流式摘要等"过程性文字"使用 secondary 字号/行高
（正文 −1 档；正文 >14 时 −2 档），且**位置与正文光学对齐**
（`thinkBody` 左缩进 = leading 宽 + gap，不是任意值）。

**证据**：`dsh` `ReasoningRow.module.css:41-51,73-77`

```css
.summary { font-size: var(--dsh-content-font-size-secondary, 13px); line-height: calc(20px + ...); }
.thinkBody { padding: 4px 0 4px calc(22px + var(--dsh-content-font-delta, 0px)); }
/* 注释：Indent under the title, which starts at leading (16 + delta) + gap 6. */
```

**违反症状**：思考文字与正文同大小同粗细，读者分不清哪段是"过程"。

## G-10 展开动画阈值 240dp（已拍板）

**规则**：可展开节点的**展开后内容高度**决定动效：

| 展开后高度 | 动效 |
|---|---|
| ≤ 240dp | 允许位移动画（纵向 expand，曲线用 M5 `settle`），仅纵向、无横向生长 |
| > 240dp | **直接切换**，不做高度动画；允许 ≤120ms 的淡入淡出做过渡 |

**为什么（反证）**：长内容做高度动画时，动画期间内容是"被压缩渲染/逐帧重新测量"的，
在移动端会明显掉帧；更关键的是**用户必须等动画结束才能开始读**——
一段两屏的思考，动画 300ms，看起来是"卡了一下"。DSH 干脆全部不做高度动画
（`ReasoningRow.tsx:38-39`），我们只在小内容上保留手感。

**证据**：`user`（2026-11-27 拍板：高内容直接切换，≤240dp 才动画）；
`dsh` `ReasoningRow.tsx:38-39`（模式切换只切 display，不 unmount）；
阈值 240dp 为 `user` 授权下的工程取值（**E1**，可调，改动需记录在此）。

**违反症状**：点开一段长思考，画面先卡顿再跳到位；或动画结束后光标位置错位。

**重要：240dp 是上限，不是下限。** 它回答"超过多少就不许动画"，**不表示"低于就必须有动画"**。
以下一律**不做高度动画**（无论高度）：浮层/弹窗出现消失、chip/tab 的出现消失、设置项帮助区展开、
开关轨道、列表项插入删除（用即时布局或 ≤120ms 不透明度过渡）。
另：必须能被系统 `prefers-reduced-motion` / Android「移除动画」整体关闭。

## G-11 命中区契约（全局，所有面板必须遵守）

**规则**：每个可点节点的命中盒必须满足三条，缺一即不合格：

```
h + 2e ≥ F          ① 高度达标（F = 最小命中高，见下）
2e ≤ g              ② 不得吃进相邻节点间距
g − 2e ≥ B          ③ 与相邻命中盒之间至少留 B 的空隙
```

其中 `h` = 视觉高、`e` = 上下扩边量、`g` = 相邻节点间距、`B` = 隔离带。

- **命中盒 = 布局盒**：扩边必须落在**布局尺寸**上（Compose 里 `padding`/包一层固定高 Box），
  **不能用 `Modifier.offset` 或绘制层扩边**（偏移/绘制不改变命中盒）。
  ⚠️ 这条在 Web 参考里没有对应证据（Web 有伪元素 `::after`），属**实现选型**，需 P4 原型验证。
- **`F` 取值**：Material/Android 规范与旧 myco `TextButton` 默认值均为 `48dp`（E0）；
  若某面板想用 `44dp`（WCAG 2.5.5），必须在面板 spec 里给出理由。
- **`B` 取值**：建议 `8dp`。⚠️ **`B` 目前无 E0 证据**（只有 Material 栅格惯例），
  一旦 P4 真机出现误触，`B` 是可调参数，调整需记录在此。
- **降级顺序（几何上装不下时，按顺序退）**：
  ① 先加大 `g`（把行距撑开）→ ② 若 `g` 不能动，改用「关键区可点、扩展区不可点」
  （例：只让标题+箭头响应，摘要区不响应）→ ③ 最后才考虑抬视觉高。
  **禁止**「硬扩边导致命中盒重叠」——那就是"点大反而变小"（mobile-adapt 的 issue #2）。
- **并排小目标**（≥2 个相邻图标按钮）强制留 `B`；整行可点的行与上下行之间若 `g ≥ 2e` 可豁免。

**为什么（反证）**：命中盒重叠时，点击落在重叠带会被**最后绘制的那个**吃掉，
用户点 A 触发 B——比"点不到"更糟，因为它破坏的是信任。

**违反症状**：点左边按钮触发右边；滑动手势被误判成点击；同一条目有时响应有时不响应。

## G-12 保存语义（已拍板 D-10）

含**自由文本 / URL / 密钥 / 数值**输入的页面 = **显式提交**（离开不写、无"放弃"按钮、离开时脏检查二次确认）；
全为**开关 / 单选 / 滑杆**的页面 = **即时写**（滑杆松手才落盘）。
**同一页不许混用**。脏检查覆盖系统返回、侧滑返回、手势关闭三条出口。

**反证**：移动端返回/侧滑是高频误触，静默丢弃整页草稿 = 用户以为已保存。

## G-13 弹层分工（已拍板 D-03）

| 场景 | 形态 | 关闭 |
|---|---|---|
| 确认 / 危险操作 / 不可逆 | 居中 Modal | 点外、返回键；**无下滑关** |
| 轻选择 / 单选 / 附件入口 / 模型选择 | BottomSheet | 下滑（仅内滚在顶时）、返回键、点遮罩 |
| 菜单 / 次级操作 | Menu / 列表 | 点外、返回键 |
| 图片查看 | Lightbox（全屏） | 返回键、关闭钮、**双击/双指缩放**（缩放态禁翻页） |

遮罩关闭判据 = **按下与松手都必须在遮罩上**（G-18）。

## G-14 转场物理（已拍板 D-07）

**一律 spring**，禁止固定时长 tween：`dampingRatio 0.86 / stiffness 420`（等效 ≈300ms）；
提交阈值 **22% 屏宽** 或 **600dp/s**；松手把末速度交给动画。
**反证**：旧版 tween 就是"手停了还顿一下"的根因。

## G-15 抽屉/面板开合手势（已拍板 D-06）

入口 = **根层内容区拖拽**，位移 **>96dp** 才消费；左缘 **20dp 让系统返回**；
深层 route 禁止滑开；打开=push、返回=pop（G-17 的栈）。

## G-16 命中区分级表（D-02 定稿，补充 G-11 的 `F`）

| 类别 | F |
|---|---|
| 输入框 / 主操作（发送） | 48dp |
| 行 / 整块可点（会话行、菜单行、设置行） | 44dp |
| **过程行（思考行、工具行）** | **32dp + 整行可点 + 横向 Bleed 8dp** |
| 密集图标（操作条） | 40dp |
| 行内片段 / 次级 | ≥36dp |
| 正文内链接 | ≥44dp |

**不得全局套用 48dp**（两家手机参考从两个方向反证）。**唯一硬约束：命中盒不得相交**；
"≥8dp 隔离带"已取消（无 E0），间距由内边距给出。

## G-17 层模型（已拍板 D-01）

**覆盖栈**：`List<PanelRoute>` + 邻接图；栈顶渲染、下层保活（深度 0–1）、≥2 冻结；返回 = pop。
禁止浮层数组式（无 pop 语义）与"并排拼贴"。

## G-18 遮罩关闭判据（已拍板 D-08）

**按下与松手都必须在遮罩上**才关闭。防止"框内拖选文字、拖到遮罩上松手"把内容关掉。

## G-19 禁止"普通透明"：只有两条视觉路线（用户 2026-11-27 定死）

**规则**：任何面板/控件只能落在这两条里，**不存在第三条**：

| 路线 | 定义 | 适用 |
|---|---|---|
| **A. 不透明 + neumorphism** | 实体底色，靠凸起/凹陷投影表达层级与深度 | 常驻元素、卡片、列表、输入区、顶栏、设置页等一切"不需要透出背景"的地方 |
| **B. 真背景模糊 + 玻璃折射** | 真 `backdrop` 模糊（重绘路径）+ 边缘折射/色散 + 镜面高光 + 内阴影 | 浮层（抽屉 / sheet / modal / 菜单 / 模型选择 / 灯箱），以及动态成本验证过关的常驻元素 |

**明令禁止**：半透明 + 无模糊的"普通透明"（含"低 tint + 高光"这种近似）。它既不是 neumorphism 也不是玻璃，是廉价感来源。

**推论**：
- 若某元素**负担不起真模糊**（滚动内容上方、低端机、API<31）→ **必须走 A（不透明 neumorphism）**，不许退化成半透明。
- API<31 没有 `RenderEffect` → 所有玻璃位置降级为 A，而不是降级为半透明。
- 之前"顶栏/输入区用半透明+高光保清晰"的建议**作废**（D-54 修正）。

**目标形态**：`docs/reports/assets/reference/glass-target-focus-pill.jpg`（用户提供的参考图）——
胶囊玻璃 + 背景色彩渗出 + 边缘折射/色散 + 沿边镜面高光 + 内阴影，**清晰但不是磨砂乳白**。

## G-20 禁用态与状态切换：不要用"离屏层"做视觉降级（实测坑）

**规则**：
1. **禁用/不可用态用色值 alpha**（改变图标与文字的 `color.copy(alpha=…)`），**不要用 `Modifier.alpha(...)`**——
   后者会创建离屏合成层，在「IME 弹出导致布局重排」之后可能**不再重绘**（实测：输入区主键在键盘弹出后消失，
   但 uiautomator 仍能看到节点、`enabled=true`、点击有效 → 是纯绘制问题，最难排查的那类）。
2. **会随状态切换尺寸/位置的区域，避免用 `AnimatedContent`**（它会引入子组合与额外层）；
   状态切换用"直切 + 色值/图标变化"（G-10 本就允许直切）。
3. 若必须用动画/离屏层，验收项里要加一条：**"在键盘弹出/收起后，该元素仍然绘制"**（真机/模拟器实拍）。

**证据（E0，本仓库实测 2026-11-27）**：`ComposerM5` 主键（发送/停止）在有字 + 键盘弹出后不绘制；
dump 证明节点存在且可点；根因是 `Modifier.alpha` 离屏层 + `AnimatedContent` 子组合在重排后未重绘。
修复后改为色值 alpha（38%）+ 图标直切。

**违反症状**：元素"点得到但看不见"；截图里缺失但自动化测试全绿（最危险的一类 bug）。
