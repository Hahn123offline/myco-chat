## 0. 一句话 + 范围

**一句话**：`chat` 面板 = 一条可滚动的会话时间线，把「用户消息 / 整轮过程（折叠控制条 + 过程组 + 思考行 + 工具行）/ 最终回答（Markdown + 代码块）/ 轮内错误与状态 / 轮尾操作条与版本切换 / 来源区」按固定顺序排成块，并负责这条时间线的滚动跟随、过程区的形态切换、以及所有消息级操作（复制、重生成、版本切换、长按菜单、编辑重发、来源查看）。

**负责**：轮内节点顺序与间距；过程组的流式封顶/定稿放开（G-03 形态 D）；思考行；工具行与工具详情「井」+ 全文页入口；消息操作条；用户消息气泡与长按菜单；编辑对话框；错误/上限/停止状态行；滚动跟随与回底钮；Markdown/代码块/表格渲染；来源区与来源 sheet（含行内引用角标的条件实现）。
**不负责**（归邻面板，本文件只引用不定义）：输入区与主键语义（`composer`；D-14 的"生成中仍可能发送"只影响本面板"不产生新行"的边界，见 §2-9）；模型/推理档位入口（`model`，D-12）；附件选择、附件条渲染与历史图片查看（`attachment`；本面板只留"气泡上方附件条槽位"）；审批/提问卡（`approval`，core 无此能力）；轮内用量 pill 与会话统计（`trajectory`，P2 §4-4 不做）；工具**全文页内的卡片渲染细节**（`tool` 面板；本面板只负责入口与 route push）；顶栏、返回栈与 insets（`base.layout`，D-01/E-01/E-02）；会话导航（`sidebar`）。

**与 P2 的四处收敛（已按拍板落实，不再讨论）**：
1. 过程行布局盒 = **32dp + font-delta**（思考行/工具行/组头）、`turn.process-control` = **33dp + font-delta**；金标准样本里"思考行 24dp"是 Web **视觉**高，D-02 把它抬成 32dp **布局盒**（文字行仍 24dp，上下各 4dp 内边距）——命中盒=布局盒，不得再用伪元素扩边（G-11）。
2. 思考行/过程组 **流式期 = 封顶内滚 + 跟尾 + 拖动即暂停；定稿后 = 不封顶**（D-11=C，G-03 形态 D）。Q-01 的"形态 A"只描述**定稿态**。
3. 消息操作条 = **常驻 + 只轮尾最后一条**（D-19=A），覆盖 P2/C-M3-05 的"每条都渲染"。
4. 来源区**必须恢复**（M-01 功能丢失修复），手机形态 = G-03 形态 C 的 **sheet**（E-17=A）；行内引用角标按 P3 指派写入设计，但**条件渲染**（数据前提见 §5 `P-CHAT-01`）。

**明确不做（P2 §4 共 18 条，这里只留一行摘要，实现时不得"顺手做了"）**：展示模式三档（Compact/Detailed/Verbose）；自动重试倒计时；赞/踩反馈；会话统计与用量 pill；compaction/context-injection/system-prompt/command-card/trigger-notice 五类 agent-only 事件行；右侧轮次导航轨道；加载更早；正文内联图片查看器/图库；工具"原始 JSON"视图；新会话分支（fork）；Inspect→执行轨迹；DSH 会话运行指示条（鲸鱼尾+计时）；引用回复/删除/回滚；聊天顶栏；提问卡/审批卡；Mermaid/KaTeX；计划卡/子代理卡/A2UI 卡。另：steering/插话行也不做（core 无 steering 事件，P2 §4-5 的派生）。

### 1.4 轮内顺序表（可实现 · 任务点 1）

> 段模型（P2 §2.0 结论）：一轮 = 若干 **block** 顺序排列；`user / turn-error / turn-max-tokens` 出现即独立根；过程成员只进「过程段组」；**最终回答先 flush 再独立**；`turn.process-control` 锚在它折叠的第一个成员之前。
> 列表实现 = **扁平 block 级 `LazyColumn`**（不是"每轮一个 item"）：这是 G-06（定稿展开组头部 sticky）与流式封顶组（内滚单 item）能同时成立的前提（见 §3 `chat.group.header` 字段 7）。

| # | block | 稳定 key | 出现条件 | 前间距 | 能否折叠/展开 |
|---|---|---|---|---|---|
| 1 | `user-message` | `turnId/user` | 每条用户消息 | 首条 12；否则 24 | 否（长按开菜单） |
| 2 | `turn-process-control` | `turnId/process-control` | 该轮 `status==closed` 且有过程内容 | 12（user 之后） | 展开=放回全部过程段（见 3–5） |
| 3 | `group-header`（段 i） | `turnId/group:i/header` | 该段有过程成员 | 段 0：16（control 后）；段 i>0：16 | 是（开合 body） |
| 4 | `group-body-streaming`（段 i，live） | `turnId/group:i/body` | 该轮**未 closed** 且组展开 | 0（紧接 header） | 组体是封顶内滚的**单个** lazy item |

**合并/切段规则（实现判据）**：
- 连续过程成员（reasoning / 工具）→ 同一段组；遇到 `user`、`turn-error`、`turn-max-tokens`、最终回答 → **flush 成独立根**（DSH `N/process-groups.ts:13,157-179` E0）。
- 无过程内容的轮**不出现**组头/控制条（不渲染空组，`C/ChatGroupSeat.tsx:108` E0 `data===undefined → return null`）。
- 一轮只有 1 段组是常态（myco core 无 steering/中间用户消息）；多段只是投影兼容，间距用上表第 3 行。

### 1.6 过程组流式封顶的 dp 换算（Q-05 落地，任务点 2）

**公式（Compose）**：`cap = min(400.dp, 0.5f × AStable)`，其中 `AStable` = **IME 收起时聊天列表可视高** = 屏高 − 系统 insets − M2 顶栏高 − composer 高。

| 设备档 | 屏（dp） | AStable（估） | 0.5×AStable | **cap = min(400, 0.5×AStable)** |
|---|---|---|---|---|
| 小屏 | 360×640 | ≈464（640−24−56−96） | 232 | **232dp** |
| 主流 | 360×800 | ≈600（800−24−56−120） | 300 | **300dp** |
| 大屏 | 412×915 | ≈715（915−24−56−120） | 357 | **357dp** |
| 平板/横屏 | AStable ≥ 800 | ≥400 | ≥400 | **400dp（取绝对值侧）** |

- 换算依据：DSH 真实值 `min(400px, 50vh)`（`C/ChatGroupSeat.module.css:86-92`）E0 + E1 平台映射（1px≈1dp）+ Q-05=A。
- **回答"具体值"**：主流手机 **300dp**；上限 **400dp**（大屏才触发）；小屏 232dp。
- AStable 的组成（insets/顶栏/composer）由 M2/composer 提供，本面板不自算；上表估算标 **我方取值（P4 真机校准）**——P4 需在至少 360×800 与 412×915 两档真机量 `0.5×AStable` 并回填本表。
- **键盘开合不改变 cap**（否则过程组高度突变、内容跳动 = G-02 同类症状）：用 IME 收起的 AStable 计一次，组合期缓存。
- 同一公式复用于：工具井（实为固定 280dp 且 280 < 任何档 cap，故写作常数）、代码体（280dp）、来源 sheet（封顶）。
