## 关键词表判据失效 → 统计判据成立

第一版用控件词表估 chrome，得 6.5%，但"有效"Top20 全是
`更多(×11313) 点踩(×5965) 回复(×5778) 评论(×3909) 关闭弹幕(×3632) …
资料卡 首页 换行 符号123` —— 词表法必然漏。

改用**无词表判据：该文本出现在多少个不同对象里**。

```
出现在 >100 个对象   42 条 distinct  →  91,598 行 = 14.4%
出现在 21-100        357 条 distinct  → 132,924 行 = 20.9%
出现在 6-20        2,481 条 distinct  →  86,033 行 = 13.5%
出现在 1-2       119,428 条 distinct  → 235,873 行 = 37.0%
```

- **42 个字符串抵掉 9 万行**（压缩比 1:2200）
- 跨对象最多的：`更多`(316 对象) `点踩`(261) `简介`(258) `评论`(242) `关闭弹幕`(236) `回复`(229)
- 只出现在 1 个对象里的样例全是真内容（群消息、文件名、拍一拍）

**结论**：结构 chrome 可以用"跨对象出现次数"识别，不需要任何 app 知识或词表。
这与设计文档"反硬规则"的原则一致，且**可测**。
