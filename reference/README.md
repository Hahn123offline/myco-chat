# 参考实现

本目录下的内容来自一条**已降级为参考地位**的探索线：安卓端设备使用痕迹的
采集、重建与检索。

> **它不构成任何约束。** 可以完全无视、重写或推翻。
> 契约只描述"若要接入则需要满足什么"，不描述"产品最终形态应该是什么"。
> 这里没有需要继承的承诺。

## 为什么值得看

不是因为它做对了，而是因为它**付过学费**：

- 一批已经验证过的实测结论（哪些 API 能拿到什么、什么方法在什么场景下不可靠），
  重做一遍成本很高
- 七个被反复翻案的话题（检索方案换了三代、出网矩阵改了三次、人名脱敏翻了四次……）
- 一份量化过的"原始数据有多脏"的基线（79% 冗余、22% 对象串台、35% 控件污染）

## 从哪开始

```
trace-memory/docs/README.md            交接说明：现状、契约、已知未完成
trace-memory/docs/INTERFACE.md         记忆层契约（如果要接入，读这份）
trace-memory/docs/ARCHIVE-INDEX.md     47 篇历史文档的分层索引
                                       （第五节"反复翻案的七个话题"最值钱）
```

## 结构

```
trace-memory/
├── docs/          5 份文档（交接说明 / 契约 / 设计定型 / 质量基线 / 历史索引）
├── app/v2/        安卓端实现（独立 Gradle 工程，12 个模块，77 个测试）
├── viz/           数据可视化小工具
└── recorder/      早期 Python 采集器（已被 app 取代）
```

`app/v2` 是**自包含**的 Gradle 工程，不会被上层构建 include，可以单独构建：

```
cd trace-memory/app/v2 && ./gradlew test
```

## 注意

- 设计文档与历史文档里可能残留真实数据片段（来自早期实验），
  已从 git 历史中清理，但仍建议不要把这里的文本当作示例数据源
- 历史文档里有大量自相矛盾的结论，**读之前先看 ARCHIVE-INDEX 的状态标注**
